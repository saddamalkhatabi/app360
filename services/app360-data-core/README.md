# App360 Data Core

خدمة بيانات Node مستقلة عن تطبيقات PWA الستاتيكية. الغرض منها أن تكون نواة اختيارية عند تشغيل App360 على خادم أو جهاز إداري، بينما تبقى تطبيقات `apps/**` قابلة للعمل من RawGitHack وPWA بدون هذه الخدمة.

## لماذا منفصلة عن pnpm workspace؟

`better-sqlite3` إضافة Native. المنصة الحالية تختبر الواجهة على Node 20 وتثبت Workspace بـ `--ignore-scripts`. لذلك تبقى هذه الخدمة مستقلة في `pnpm-workspace.yaml` ويثبت اعتمادها من داخل مجلدها فقط، حتى لا يصبح تشغيل التطبيقات الستاتيكية مشروطا ببناء Native module.

## الإصدارات المثبتة

- `knex: 3.3.0`
- `better-sqlite3: 11.10.0`
- Node: `>=20 <22` لهذه النسخة من الخدمة.

## تشغيل محلي

```bash
cd services/app360-data-core
npm install
npm run reset
npm run smoke
```

يمكن تغيير ملف القاعدة:

```bash
APP360_DB_FILE=/path/to/app360.sqlite3 npm run migrate
```

## المجلدات

- `migrations/`: بنية القاعدة فقط، ولا توضع بيانات أولية فيها.
- `seeds/`: حسابات/مستخدمون تجريبيون، سجل التطبيقات، وعقود أنواع المحتوى.
- `src/contracts.js`: التحقق من حزم AI وفقا لـ `data/ai-content-contracts.json`.
- `src/repository.js`: استيراد حزم AI مع revisions، جلسات وأحداث، وoutbox للمزامنة.
- `src/file-store.js`: حفظ الملفات على القرص مع `sha256` وتسجيل metadata في SQLite.
- `var/`: قاعدة التطوير والملفات المحلية، ولا ينبغي رفعها للمستودع.

## مبدأ المستخدمين حاليا

الحسابات في `seeds/001_users.js` تجريبية فقط: ولي أمر، طفلان، مدرب ومسؤول مؤسسة. جدول `external_identities` يحجز مكان الربط المستقبلي مع نظام الريلز الآمن 360 ولا ينفذ مزامنة أو تسجيل دخول حاليا.

## مبدأ AI

لا يوجد اتصال بمزود AI داخل الخدمة أو التطبيقات. التطبيق يبني Prompt، المستخدم يرسله إلى المزود الذي يختاره، ثم يعيد JSON/الصور. حزمة JSON تمر بالتحقق ثم تسجل كـ draft مع revision history. لا تنتقل لمرحلة نشر إلا بقرار مراجعة منفصل.

## الملفات والصور

في PWA الستاتيكي يمكن الاحتفاظ بصورة صغيرة كـ Data URL مؤقتا. في Data Core تحفظ الصورة كملف على القرص، وتسجل في جدول `files` مع الحجم والنوع و`sha256`، ثم تربط بالمحتوى عبر `content_file_links`. هذا يمنع تضخم SQLite بصور Base64.

## التوسع لاحقا

عند بناء مزامنة Safe Reels 360 يفضل أن تعمل عبر Adapter يقرأ `external_identities` ويكتب إلى `sync_outbox`. لا تربط معرف المستخدم الخارجي مباشرة بمفاتيح `content_items` أو `learning_events`؛ تبقى هوية App360 الداخلية ثابتة حتى لو تغير مزود الهوية.
