# App360 Family Relay

خادم Node.js مستقل لقناة التحكم في جلسة العائلة في App360.

## لماذا؟

قناة التحكم العائلية (الحضور، heartbeat، السياسات، فتح التطبيقات، استعادة الجلسة) لا ينبغي أن تعتمد على PeerJS/WebRTC العام. هذا الخادم يستخدم WebSocket مباشر ويحتفظ باتصالات الأطفال لمدة سماح قصيرة عند تحديث صفحة الأب ثم يعيد ربطها فور عودته.

الصوت ومشاركة الشاشة يمكن أن يبقيا على WebRTC بصورة منفصلة؛ هذا الخادم مخصص أولاً للتحكم والحضور الموثوق.

## التشغيل

من جذر المستودع:

```bash
node services/family-relay/src/server.js
```

أو:

```bash
pnpm --filter @app360/family-relay start
```

ثم افتح:

```text
http://localhost:8787/
```

وعلى جهاز آخر في نفس الشبكة استخدم عنوان IP للجهاز المشغل للخادم، مثل:

```text
http://192.168.1.10:8787/
```

الخادم يخدم App360 نفسه ويحقن إعداد `APP360_FAMILY_WS_URL` تلقائياً، لذلك لا تحتاج إلى ضبط رابط WebSocket يدوياً.

## المسارات

- `/` — تطبيق App360.
- `/family-ws` — WebSocket الخاص بجلسة العائلة.
- `/health` و`/family-health` — حالة الخادم وعدد العملاء والغرف.

## الاستعادة بعد Refresh

إذا حدث Refresh للأب، يحتفظ الخادم باتصالات الأطفال افتراضياً لمدة 15 ثانية. عند عودة الأب بنفس رمز الجلسة يعيد الخادم ربط الاتصالات نفسها دون إجبار الطفل على بناء جلسة جديدة.

## متغيرات البيئة

- `PORT` — المنفذ، افتراضياً `8787`.
- `HOST` — افتراضياً `0.0.0.0`.
- `APP360_ROOT` — جذر ملفات App360 إذا لم يكن الخادم داخل المستودع نفسه.
- `FAMILY_HOST_GRACE_MS` — فترة انتظار عودة الأب، افتراضياً `15000` ms.
- `FAMILY_PENDING_CONNECT_MS` — انتظار اتصال الطفل قبل ظهور الأب، افتراضياً `18000` ms.
- `FAMILY_MAX_MESSAGE_BYTES` — الحد الأعلى للرسالة.
- `FAMILY_RATE_MAX` — عدد الرسائل المسموح به لكل نافذة 10 ثوانٍ.
- `APP360_ALLOWED_ORIGINS` — قائمة Origins مفصولة بفواصل عند تشغيل relay منفصلاً عن الواجهة.

## الاختبار

```bash
node --test services/family-relay/test/relay.test.js
```

الاختبارات تغطي التبادل ثنائي الاتجاه واستعادة اتصال الطفل بعد Refresh للأب.
