# الخدمات المشتركة — services/

هذا المجلد لأي Backend/Node.js يحتاجه أكثر من تطبيق أو يحتاج أسرارًا/معالجة لا يجب وضعها داخل المتصفح.

## متى نبني Service بدل Package؟

ابنِ Service فقط عندما توجد حاجة إلى واحد أو أكثر من:

- API key أو Secret لا يجوز كشفه للمتصفح.
- معالجة ثقيلة مثل تحويل الصوت/الفيديو.
- حالة مشتركة بين أجهزة أو مستخدمين.
- بوابة موحدة لمزود خارجي (AI/TTS/Storage).
- سياسة مركزية للتكلفة، الحدود، التدقيق أو الخصوصية.

إذا كان الكود يمكنه العمل محليًا بلا سر وبلا حالة مركزية، فغالبًا مكانه `packages/` أو داخل التطبيق.

## Node.js وnode_modules

المستودع Monorepo عبر **pnpm workspaces**. لا تنشئ `node_modules` وتثبيتًا منفصلًا يدويًا لكل خدمة.

من جذر المستودع:

```bash
pnpm install
pnpm --filter @app360/<service-name> dev
```

لدينا lockfile واحد عند أول Install، واعتمادات Workspaces مشتركة، وpnpm يقلل النسخ الفيزيائية للحزم عبر مخزنه content-addressed. الإعداد `node-linker=hoisted` يجعل تجربة الأدوات القديمة أبسط مع بقاء إدارة الاعتمادات مركزية.

## المسار

```text
services/<service-slug>/
├─ package.json
├─ README.md
├─ src/
├─ test/
└─ .env.example
```

الخدمة يجب أن تكون صغيرة ومحددة الغرض. لا نبني Backend واحدًا ضخمًا لكل شيء.

## خدمات مرشحة لاحقًا

- `ai-gateway` — بوابة AI موحدة.
- `tts-renderer` — توليد حزم أصوات مشتركة.
- `media-worker` — ffmpeg/تحويل وسائط مركزي.
- `progress-api` — مزامنة التقدم إذا احتجنا حسابات متعددة الأجهزة.
- `content-api` — عند تجاوز المحتوى الثابت قدرة ملفات JSON.

يجب ألا تنشأ هذه الخدمات قبل وجود تطبيق حقيقي يحتاجها.
