# متطلبات ما قبل البناء — أستطيع خطوة: روتيني المصور

هذه الوثيقة **ملزمة ومكملة** لـ `PROMPT_AR.md` و`BUILD_SPEC.md`. عند التعارض، تكون هوية التطبيق وعقده من الكتالوج ثابتة، وتكون متطلبات النضج والتنفيذ هنا هي الحد الأدنى المطلوب قبل إعلان التطبيق جاهزًا.

اقرأ أيضًا `docs/IMPLEMENTATION_MATURITY_BASELINE_AR.md` قبل بدء البرمجة.

## خصوصية هذا التطبيق

هذا التطبيق ليس قائمة مهام للكبار مصغرة للطفل، وليس نظام نقاط أو مكافآت. وظيفته تحويل روتين واقعي إلى **تسلسل بصري قابل للتنفيذ والتعديل** يخفف الغموض ويزيد قدرة الطفل على فهم الخطوة الحالية وما بعدها.

الطفل قد لا يقرأ؛ لذلك الصورة والصوت والرمز هي الواجهة الأولى، بينما التفاصيل النصية للمرافق.

## الحلقة العملية الأساسية

1. يختار المرافق قالب روتين أو يبدأ فارغًا.
2. يضيف 1–8 خطوات بصور واضحة من الموارد المشتركة أو صورة محلية.
3. يحدد لكل خطوة: العنوان، صورة/رمز، نطق اختياري، قابلية إعادة الترتيب، ومقدار المساعدة المتوقع.
4. يختار وضع العرض: خطوة واحدة / الآن وبعد ذلك / التسلسل المصور.
5. يبدأ التنفيذ الحقيقي خارج الشاشة قدر الإمكان.
6. لكل خطوة يسجل: تم باستقلال / تم بمساعدة / تجاوزناها / توقفنا الآن.
7. يستطيع الخروج والعودة دون فقدان موضعه.
8. بعد الجلسة يقترح التطبيق تعديلًا وصفيًا واحدًا للمرة التالية، لا تقييمًا للطفل.

## الشاشات والحالات المطلوبة

### شاشة المكتبة
- قوالب: الاستيقاظ، اللبس، الحمام، غسل اليدين، الوجبة، ترتيب اللعب، الخروج، العودة، وقت النوم.
- بحث وفلاتر بسيطة للمرافق.
- زر «ابدأ روتينًا فارغًا» واضح.

### مصمم الروتين
- إضافة/حذف/نسخ خطوة.
- تغيير الصورة من الموارد المشتركة أو الجهاز.
- إعادة ترتيب بالسحب **وبأزرار أعلى/أسفل بديلة**.
- لا تعتمد الوظيفة على Drag & Drop أو Pointer Events.
- معاينة فورية لوضع الطفل.

### وضع الطفل
- خطوة واحدة كبيرة ومنظمة، لا لوحة إدارة كاملة.
- زر صوت اختياري.
- «تم» و«مساعدة» و«تجاوز» فقط عند الحاجة، ويمكن للمرافق إخفاؤها أو إدارتها.
- لا ينتقل التمرير فوق البطاقة إلى الخطوة التالية؛ Shared Touch Guard إلزامي.

### الآن وبعد ذلك
- بطاقتان واضحتان فقط.
- لا تعرض بقية التسلسل إذا اختار المرافق هذا الوضع.

### مراجعة المرافق
- ما الذي تم؟
- أين احتاج مساعدة؟
- هل كان عدد الخطوات كثيرًا؟
- تعديل واحد مقترح للمرة القادمة.

## نموذج البيانات

حد أدنى مقترح:

- `routine`: id, title_ar, created_at, updated_at, display_mode, archived.
- `steps[]`: id, order, label_ar, image_ref, local_image, speech_ar, reorderable, optional.
- `run`: id, routine_id, started_at, stopped_at, current_step_id, status.
- `step_results[]`: step_id, outcome(independent|assisted|skipped|stopped), assistance_note, at.
- `reflection`: run_id, what_helped, what_to_change_next.

كل التخزين Local-first. لا ترفع صور الأسرة أو الملاحظات افتراضيًا.

## المحتوى الأولي المطلوب

يجب ألا يبدأ التطبيق بقالب واحد أو اثنين فقط. وفر مجموعة أولية عملية تغطي على الأقل:

- روتين صباحي.
- غسل اليدين.
- تنظيف الأسنان.
- دخول الحمام.
- ارتداء الحذاء/الملابس.
- وجبة بسيطة.
- ترتيب الألعاب.
- الاستعداد للخروج.
- العودة للمنزل.
- روتين النوم.

كل قالب قابل للنسخ والحذف والتعديل الكامل.

## التكامل مع التطبيقات السابقة

- استخدم Relative deep links فقط.
- يمكن لخطوة اختيارية أن تفتح نشاطًا قصيرًا في `say-and-name` لتسمية غرض، أو `imitate-one-step` لتقليد حركة، أو `drawing-writing-foundations` للرسم، ثم تعود إلى الروتين عبر `return_to` دون فقدان `current_step_id`.
- لا تنسخ محتوى تلك التطبيقات داخل الروتين.
- سجل opened/completed/returned بالـ `launch_id` إذا استُخدم التكامل.

## Big TAB Android 4.4.2

- ES5 للوظائف الأساسية.
- Flexbox فقط للهيكل الأساسي.
- لا CSS Grid ولا clamp ولا container queries كشرط.
- Shared App360 Shell إلزامي: 🏠 الرئيسية + Responsive Policy + Touch Guard.
- النص على التاب الكبير لا يتضخم؛ استخدم مقياس التابلت المشترك، مع بقاء أهداف اللمس قرابة 48px.
- لا تستخدم Modal كثيف كمسار بناء الروتين؛ المصمم شاشة عادية قابلة للتمرير.
- التمرير فوق بطاقة أو زر لا ينفذه عند رفع الإصبع.

## Offline وPWA

- إنشاء/تعديل/تنفيذ الروتين يعمل دون اتصال.
- الصور المشتركة الضرورية تدخل Cache.
- الصور المحلية تستمر بعد الإغلاق إذا كان التخزين متاحًا.
- تحديث Service Worker لا يمسح الروتينات القديمة؛ أي تغيير schema له migration أو fallback واضح.

## السلامة والتجربة

- لا توجد سلاسل نجاح أو خصم مكافآت أو عبارات «فشل».
- التوقف أو التجاوز طبيعي.
- لا تفترض أن الاستقلالية الأفضل دائمًا هي الأقل مساعدة؛ المرافق يصف مقدار الدعم المناسب.
- لا تجعل الروتين صارمًا لدرجة يمنع التغيير؛ يجب أن توجد خطوة «تغيرت الخطة» أو إمكانية استبدال خطوة بسرعة.

## اختبارات القبول الخاصة

- إنشاء روتين من 5 خطوات ثم إعادة ترتيبه بالأزرار على Android 4.4.
- سحب الصفحة فوق خطوة لا يفعّلها.
- Tap قصير يفتح الخطوة مرة واحدة فقط.
- تنفيذ خطوتين ثم إغلاق التطبيق وفتحه: يعود إلى الخطوة الثالثة.
- التحويل من «التسلسل» إلى «الآن وبعد ذلك» لا يغيّر بيانات الروتين الأصلية.
- فتح تطبيق مساعد ثم العودة يحفظ موضع التنفيذ.
- طباعة الشريط تعرض نفس الصور والترتيب الموجود على الشاشة.
- تعطيل الصوت لا يمنع فهم الروتين.
- تغيير الاتجاه رأسي/أفقي لا يضخم النص ولا يقطع الأزرار.

## Definition of Done

لا يعتبر التطبيق منجزًا بوجود المصمم فقط. يجب أن تعمل دورة: **إنشاء → حفظ → تنفيذ → توقف/عودة → نتيجة لكل خطوة → مراجعة → طباعة/تصدير** على الهاتف والتابلت والحاسوب، ثم يختبر Big TAB فعليًا قبل إعلان دعم الجهاز القديم.
