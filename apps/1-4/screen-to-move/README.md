# لنلعب الآن: بديل الشاشة مع المرافق

هوية التطبيق: `a1-screen-move`  
المسار الرسمي: `apps/1-4/screen-to-move/`

## ما بُني في النسخة التجريبية

تطبيق محلي للفئة 1–4 يحوّل المشاهدة إلى لعب واقعي مع المرافق، مع بديل تفاعلي على الشاشة عندما لا تتوفر الطباعة. النسخة الحالية تضم **20 تجربة أصلية** موزعة بالتساوي على **4 مستويات**، وتغطي مطابقة الصور، الألوان، الحيوانات، الفواكه والخضروات، وسائل النقل، التوصيل بالنقاط، المسارات، الذاكرة، الأنماط، الفرز، التسلسل، البازل والابتكار المشترك.

لكل تجربة:
- خمس لقطات بصرية متتابعة، ثم عرض كل اللقطات معًا.
- قائمة مواد واضحة.
- مسار ورقي/واقعي ينتهي بإغلاق النشاط دون مطالبة بالعودة.
- ورقة عمل A4 قابلة للطباعة أو التنزيل بصيغة SVG.
- بديل تفاعلي على الشاشة باللمس أو الرسم.
- نهاية صريحة لا تشغّل لعبة أخرى تلقائيًا.
- مراجعة اختيارية للمرافق فقط، تحفظ محليًا إن كان التخزين متاحًا.

يوجد أيضًا:
- لوحة رسم مشتركة مستقلة للطفل والمرافق.
- سجل محلي اختياري مع تصدير JSON وحذف كامل.
- PWA مستقلة وOffline-first بعد التحميل الأول.
- زر تثبيت وزر فحص تحديث.
- RTL وأزرار لمس كبيرة ودعم الفأرة ولوحة المفاتيح في عناصر الواجهة.

## الحدود التربوية والخصوصية

التطبيق لا يستخدم كاميرا أو ميكروفون، ولا يراقب تنفيذ الطفل خارج الشاشة، ولا يدعي قياس مهارة الطفل أو إثبات أثر تربوي. استخدام الشاشة عند الطرف الأصغر من الفئة موجّه أساسًا للمرافق، واللعب الواقعي هو المسار المفضل.

## التخزين

المفتاح المحلي:
`app360:a1-screen-move:schema2`

البيانات المحفوظة اختيارية وتقتصر على:
`session_id` و`task_id` و`attempts` و`artifact` و`reflection` و`assistance_level`.

إذا تعذر `localStorage` تستمر الممارسة دون حفظ دائم ويظهر تنبيه واضح.

## التحقق

داخل Workspace:
```bash
pnpm --filter @app360/app-screen-to-move validate
```

التحقق المحلي للتطبيق يفحص:
- سلامة JavaScript.
- وجود 20 تجربة بالضبط.
- توزيع 5 تجارب لكل مستوى من المستويات الأربعة.
- اكتمال الحقول اللازمة للصور والخطوات والمواد وورقة العمل.

## قبل تحويل الحالة إلى live

الحالة تبقى `planned`/قيد القبول رغم وجود تنفيذ عامل حتى يتم:
1. تجربة مستخدم موثقة مع مرافق وطفل.
2. اختبار الهاتف والتابلت والحاسوب رأسيًا وأفقيًا.
3. اختبار التثبيت والعمل بعد فصل الإنترنت.
4. اختبار تحديث Service Worker دون فقد السجل.
5. تحديث سجل `data/catalog.json` وفق نتيجة القبول، ثم تشغيل `node tooling/build-blueprints.js` و`node tooling/validate-platform.js`.

لا يُدّعى دعم جهاز Android قديم بعينه قبل اختباره فعليًا.
