# قلب محتوى AI والبيانات في مختبر التطبيق 360

## الهدف

توحيد طريقة إضافة محتوى جديد إلى تطبيقات App360 الحالية والمستقبلية، سواء كان المحتوى بطاقة كلمة، تجربة، لعبة، ورقة تدريب، شكل رسم، موقفا شعوريا أو قالب خطة تشغيل.

المبدأ الأساسي: **الذكاء الاصطناعي مساعد لإنشاء مسودة محتوى، وليس مصدرا موثوقا ينشر مباشرة.** لا يوجد اتصال تلقائي بمزود AI، ولا ترسل بيانات طفل أو أسرة تلقائيا.

## رحلة المحتوى

1. التطبيق يحدد `app_id` ونوع المحتوى.
2. المستخدم يختار العمر/المستوى/اللغة/الموضوع وخيارات المساعدة.
3. استوديو AI يبني Prompt صارما يطلب JSON فقط.
4. المستخدم ينسخ الـPrompt إلى أداة AI يختارها.
5. يعيد JSON، ويمكنه إرفاق صور مستقلة.
6. التطبيق يتحقق من `app_id`, `content_type`, الحقول المطلوبة، ثم يحفظ حزمة محلية كمسودة.
7. يمكن اعتماد الحزمة محليا وإتاحتها لمحرك التطبيق عبر `window.APP360_AI_CONTENT.getPublished()`.
8. عند تشغيل Data Core يمكن استيراد نفس الحزمة إلى SQLite، وتصبح كل إعادة استيراد Revision جديدة بدلا من الكتابة فوق السجل.

## عقد الحزمة العام

```json
{
  "schema_version": "1.0",
  "app_id": "a1-first-words",
  "content_type": "word_cards",
  "title": "حزمة محتوى",
  "source": {"kind": "ai-assisted", "review_required": true},
  "items": [],
  "assets": []
}
```

المرجع المركزي الحالي: `data/ai-content-contracts.json`.

## أنواع المحتوى الحالية

### كلماتي مع أشيائي
- بطاقات كلمات.
- تصنيف كلمات كامل.
- صور واضحة + نص نطق عربي/إنجليزي.

### دوري ودورك
- تجربة تقليد/تبادل دور.
- خمس خطوات Storyboard.
- صورة أو Storyboard خارجي يمكن استيراده.

### ألعاب إبداعية
- لعبة إلكترونية.
- ورقة تدريب/نسخة ورقية.
- صور عناصر + نسخة بدون شاشة + قواعد الجولة.

### الرسم والكتابة
- قالب رسم/تتبع جديد.
- صورة/ختم بصري جديد.

### مشاعري معك
- موقف شعوري/سلوكي جديد.
- مساعدة عمرية جديدة.
- يمنع تحويل السلوك إلى تشخيص قطعي أو وصف علاج مضمون.

### مخطط التشغيل 360
- قالب خطة تشغيل جديد متعدد التطبيقات والخدمات.

## واجهة AI المشتركة

`assets/js/ai-content-studio.js`

يتم تحميلها تلقائيا بواسطة `assets/js/legacy-compat.js` داخل التطبيقات. الواجهة تدعم:

- مولد Prompt حسب التطبيق ونوع المحتوى.
- خيارات مساعدة قبل بناء Prompt.
- نسخ Prompt.
- لصق JSON أو اختيار ملف JSON.
- استيراد صور متعددة.
- التحقق قبل الاستيراد.
- مكتبة محلية لحزم AI Draft/Published.
- تصدير JSON.
- أحداث DOM مشتركة:
  - `app360:ai-content-ready`
  - `app360:ai-content-imported`
  - `app360:ai-content-status`
  - `app360:ai-content-deleted`

والواجهة البرمجية:

```js
window.APP360_AI_CONTENT.getPacks()
window.APP360_AI_CONTENT.getPublished('content_type')
```

هذا هو جسر التكامل الذي يمكن لكل محرك تطبيق أن يقرأ منه المحتوى المعتمد، دون ربط محرك AI بمنطق التطبيق نفسه.

## الصور

في المتصفح تحفظ الصور الصغيرة مؤقتا داخل الحزمة المحلية باستخدام Data URL مع حد للحجم والعدد. هذا مناسب للاختبار والعمل Offline لكنه ليس التخزين المؤسسي النهائي.

عند تشغيل Data Core:

- الصورة تحفظ في نظام الملفات.
- يسجل `sha256`, MIME, size, owner والموقع في جدول `files`.
- الربط بالمحتوى يتم عبر `content_file_links`.
- لا نخزن الصورة Base64 داخل SQLite.

## لماذا Knex + better-sqlite3؟

Knex يعطينا migrations/seeds واستعلامات منظمة، ويدعم `better-sqlite3` كـSQLite client. better-sqlite3 مناسب لنواة محلية/خادم صغير إلى متوسط، مع WAL وforeign keys. لو تحول النظام لاحقا إلى حمل مؤسسي كبير جدا أو كتابة متزامنة كثيفة، يبقى Repository/Knex نقطة انتقال أسهل إلى PostgreSQL بدل ربط التطبيقات مباشرة بSQLite.

## المستخدمون والمزامنة

في هذه المرحلة لا يوجد Login حقيقي داخل App360 Data Core. نستخدم Users/Accounts من seeds حتى نثبت العلاقات وتسجيل الأحداث. `external_identities` يحجز الربط المستقبلي مع الريلز الآمن 360:

- لا نستخدم External ID كمفتاح داخلي.
- المزامنة المستقبلية تكتب/تقرأ Mapping فقط.
- الأحداث تبقى مرتبطة بـApp360 user_id الثابت.

## معيار التطبيق الجديد

أي تطبيق جديد يجب أن يملك من البداية:

1. `app.json` به `app_id/slug/age_group` وCapability `ai.content-import` عند التفعيل.
2. `links.json` للتطبيق/التصنيفات/الخدمات/العناصر التي يمكن فتحها مباشرة.
3. عقد AI في `data/ai-content-contracts.json` يحدد أنواع المحتوى والحقول المطلوبة ومثال JSON.
4. تحميل `legacy-compat.js` أو `ai-content-studio.js` مباشرة.
5. Adapter اختياري يقرأ `APP360_AI_CONTENT.getPublished()` لدمج المحتوى داخل محرك التطبيق الأصلي.
6. Validation وRevision history قبل أي نشر مؤسسي.

## المرحلة القادمة

بعد تثبيت القلب الحالي يمكن بناء Adapters أعمق لكل تطبيق، مثل:

- إدخال بطاقة كلمة مولدة مباشرة إلى مكتبة الكلمات.
- تحويل Game JSON إلى لعبة تفاعلية كاملة.
- تحويل Worksheet JSON إلى صفحة A4 قابلة للطباعة.
- استخدام صورة AI كStamp أو Trace Guide في لوحة الرسم.
- إدخال مواقف شعورية جديدة إلى محرك الترشيح بعد مراجعة بشرية.
- نشر قالب خطة جديد مباشرة إلى مكتبة مخطط التشغيل 360.

هذه المرحلة التالية لا تحتاج تغيير القلب؛ فقط Adapter خاص بكل نوع محتوى.
