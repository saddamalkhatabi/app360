# خطة صوت SILMA للفئة العمرية 1–4 — نسخة مراجعة منعزلة

> الحالة: تجهيز وحصر المحتوى فقط. لا توجد ملفات SILMA مولدة في هذه النسخة بعد، ولا تعديل على تطبيقات الطفل، ولا نشر على Railway، ولا دمج إلى main أو family-school-360-preview.

## الهدف

أصوات عربية محفوظة لكل لعبة جاهزة وتجربة وروتين وخطوة وسؤال وخيار يحتاج نطقًا، مع تأشير بصري **للعنصر أو الزر أو المشهد المقصود** أثناء التعليمات، وليس تظليلاً متزامناً للكلمات. الطفل يستطيع فهم التشغيل الأول وإعادة النطق باللمس، مع احترام عمره وأمان المواقف الحياتية.

## الجرد القائم على ملفات المصدر

- `screen-to-move`: 170 لعبة، تحتوي 850 خطوة إرشادية وخانة عنوان لكل لعبة و49 سؤالًا صريحاً من نوع `prompt`؛ خيارات الرموز والصور تحتاج تسمية صوتية مناسبة بعد المراجعة، وليس قراءة الرمز حرفياً.
- `imitate-one-step`: 200 تجربة بواقع 1,000 خطوة، و200 عنوان. **معظم الخطوات موجهة للمدرب بصيغة «دع الطفل»، لذا يجب صياغة نص تسجيل مختلف مبسط للطفل دون مس النصوص القائمة.**
- `my-little-routine`: 50 روتيناً بواقع 250 خطوة و50 عنواناً؛ المصدر الفعلي بعد تحديثات storyboard v6 وv7، لا من البيانات القديمة وحدها.
- المجموع الحالي للتطبيقات الثلاثة: 2,100 خطوة + 420 عنواناً + 49 سؤالاً = **2,569 وحدة صوت مصدرية أولية**، قبل نصوص الاختيارات والتلميحات والتشجيع.
- ملفات الجرد المرفقة `tooling/age1-4-silma/worker-*-source-inventory.json` مسودات مصدر وليست مقاطع جاهزة أو معتمدة للنطق.

## ملكية التكامل بعد توليد المقاطع بالتوازي

- العامل 1: محول الصوت والتأشير في `screen-to-move`، ثم `picture-puzzles`.
- العامل 2: محول `imitate-one-step`، ثم `sensory-motion-missions`.
- العامل 3: محول `my-little-routine`، ثم `calm-with-me` و`plan-runner-360`.

- العامل 5 (مراجعة مستقلة): اختبار تغطية كل البنود والروابط والأصوات والعناصر المؤشّر إليها والتفاعل اللمسي وعدم الرجوع/التقدم فجأة، ثم تقرير قبول/رفض لكل تطبيق.

**ملاحظة**: خططنا هنا لتوزيع العمل؛ لم تُشغّل خمسة وكلاء برمجيين مستقلين بعد.

## عقد الملفات الصوتية

المسار المرشح لكل عنصر: `apps/1-4/<app>/audio/silma/items/<id>/`.

- `title.mp3`: عنوان التجربة/الروتين قبل البدء، ويجوز دمجه في التعليمة الأولى إذا كان أوضح للطفل.
- `step-01.mp3` ... `step-05.mp3`: تعليمات الخطوات الدائمة، لا تستبدل بنطق متصفح إلا عند فشل التحميل في سياق غير اختباري.
- `question.mp3`: سؤال اللعبة عندما يكون موجوداً، ويشير أثناء تشغيله إلى منطقة الاختيارات.
- خيار مصوّر لا يفهمه SILMA كنص يحتاج `spokenLabel` بشري الاعتماد، ولا يجري نطق emoji الخام.
- عبارات التشجيع المتكررة يمكن مشاركتها كأصول مضغوطة مع بقاء خريطة لكل عنصر وأحداثه.
- نص `voiceText` يجاز قبل التوليد؛ لا يجوز رفع MP3 ناتجة من النصوص الخاصة بالمدرب كما هي باعتبارها تعليمات للطفل.
- إنشاء ملفات MP3 مسبقاً وقت البناء، لا تشغيل SILMA على جهاز الطفل أو Railway المباشر. تضاف خريطة صوت منفصلة لكل تطبيق، مع تحقق SHA/الحجم والتخزين المرحلي.

## عقد التفاعل والتأشير المرئي

1. بدء أول استخدام: نطق قصير «هذه اللعبة ...»، تحديد بصري لمكان البدء لمدة النطق، وزر «اسمع مجدداً». تذكر إكمال المقدمة في تخزين محلي منفصل دون تغيير مفاتيح إنجاز الطفل.
2. لكل سؤال: نطق السؤال أولاً؛ إبراز منطقة السؤال ثم منطقة الخيارات؛ إظهار حلقة/وهج واضح على **حقل الاختيار أو القطع ذات الصلة** مع نطق «اختر ...»، دون كشف الإجابة.
3. لكل خطوة: عند عرض مشهد/خطوة جديدة، يبدأ MP3 المرتبط بمعرّفها، ويضيء العنصر المقصود إلى انتهاء الصوت. لا ينتقل تلقائياً إلى الخطوة التالية عند اكتمال الصوت إلا إذا كانت التجربة أصلاً تعتمد ذلك صراحة.
4. لمس الطفل/النقر يظل قابلاً للعمل طوال الصوت؛ عند تغيير المشهد أو بدء صوت جديد يُلغى السابق. يمنع التزاحم/التكرار الفوري للأصوات.
5. التأشير `pointer-events:none` ولا يحجب العناصر أو يعطّل السحب، ويُستخدم CSS بسيط متوافق مع الأجهزة القديمة حيث أمكن، مع وضع بديل إذا لم يدعم المتصفح حركة التأشير.
6. لا تستخدم المحاذاة الحرفية لكلمات النص؛ التزامن المطلوب مع العنصر المرئي/المشهد/السؤال، وليس كل كلمة.
7. يمكن للمدرب تعطيل الظهور التمهيدي أو إعادة تفعيله، وإسكات الصوت والتشغيل عند الطلب. لا تعديل لخوارزميات اللعبة أو نموذج البيانات.
8. تبقى الملفات الصوتية قابلة للاستخدام دون إنترنت بعد تخزينها، مع تحميل تدريجي وعدم تحميل آلاف الملفات دفعة واحدة.

## أمان الأطفال وضمان الجودة

- الأنشطة التي تتضمن ماء أو مكونات صغيرة أو حماماً أو حركة في الخارج لا يجوز وصفها بأنها آمنة دون إشراف؛ تفرّق الواجهة بين وضع الطفل الذاتي على الشاشة والنشاط الواقعي بمرافقة.
- لا تروّج اللوحة إلى وعود بنجاح استقلالية كل طفل بعمر سنة–أربع سنوات؛ تقاس قابلية الفهم وفق المرحلة والقدرة.
- اختبار سماعي عربي بشري لتصحيح التشكيل والمعنى وجودة الصوت، واختبار متصفح حقيقي للأجهزة القديمة والجديدة.
- قبل القبول: اكتمال الملف لكل حدث ظاهر، وعدم تأثر السحب والتبديل والتخزين المحلي والإعدادات والصوت القديم، وإمكانية إعادة النطق وتعليق المؤشر عند مغادرة المشهد.
- مدخلات ينشئها المدرب أثناء التشغيل ليست جزءاً من مكتبة الصوت الثابتة؛ تستعمل نطق المتصفح الاختياري فقط أو تُحوّل إلى ملفات صوتية عند إعداد المحتوى مستقبلاً.

1. نقطة الأساس: `family-school-360-preview` وقت إنشاء الفرع الحالي؛ لا تحديث على `main` أو Railway أو `.github/workflows` العام.
2. العامل يعدل مسارات الصوتيات وملفات المحول المسموح بها لتطبيقه فقط؛ لا يستبدل محرك السحب أو ملفات shared-assets أو service workers بلا مراجعة مستقلة.
3. مخرجات العمال الأربعة ملفات منفصلة؛ يُجمع فهرسها عند اختبار التكامل بعد نجاح جميع المراجعات.
4. يجري اختبار الرابط التجريبي الثابت بمعرّف الالتزام بعد نشر فرع الاختبار بصورة مستقلة، وليس باستخدام دومين اللايف.
5. قبول العامل الخامس لا يؤدي تلقائياً إلى دمج PR أو نشر. الدمج يظل بقرار المستخدم، وتظل نقطة الاسترجاع الحية محفوظة.
6. بعد القبول تبقى علامة النسخة الأصلية والالتزام المثبت، ويمكن التخلص من الملفات والفروع المؤقتة غير المستخدمة.
