# تجربة مسار school-data

المسار الافتراضي للتثبيت الذي لا يحتوي بيانات قديمة أصبح:

`services/app360-data-core/school-data/app360.sqlite3`

ومجلد المرفقات:

`services/app360-data-core/school-data/uploads`

المجلدان موجودان في المستودع بملفات .gitignore، دون أي بيانات أو أسرار. مزامنة main تنشرهما، لكن صلاحيات الكتابة الفعلية يحددها خادم الاستضافة؛ تغيير الاسم ليس ضماناً لحل مشكلة الصلاحيات.

إذا احتوى var على قاعدة موجودة أو ملفات WAL/SHM أو مرفقات، يستمر التطبيق باستخدام المسار القديم ولا ينقل البيانات أو ينشئ بديلاً فارغاً. إذا كان var مفقوداً أو فارغاً يستخدم school-data. إذا تعذر فحص var بسبب صلاحيات أو رابط مكسور يتوقف برسالة تخزين بدلاً من تجاهل البيانات المحتملة. قيم APP360_DB_FILE وAPP360_UPLOAD_ROOT الصريحة تبقى ذات أولوية.

Build Command: `npm run build`

Start Command: `node services/family-relay/src/server.js`

أبقِ APP360_STORAGE_DIAGNOSTICS=1 أثناء التجربة. بعد النشر وإعادة التشغيل جرّب الدخول. عند استمرار الخطأ أرسل السطر الجديد school-storage-paths؛ يجمع المسار الفعلي وحالته في سطر واحد قبل التقرير المطول. لا يحتوي مفتاح الربط. ثم أرسل سطر APP360_DATA_CORE الجديد.

لا يحتاج هذا التغيير باتشاً للريلز، ولا تثبيت better-sqlite3 يدوياً على Node 22. لا ترفع قاعدة بيانات الجهاز المحلي إلى الاستضافة.
