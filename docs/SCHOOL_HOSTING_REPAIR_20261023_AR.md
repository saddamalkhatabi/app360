# إصلاح بدء خدمة حسابات المدرسة — 23 أكتوبر 2026

## ما ثبت وما لم يثبت

فحص المدرسة العام أعاد `503 data_core_dependencies_missing`. السجل المقدم بتاريخ 21 أكتوبر أظهر `ENOENT` أثناء إنشاء `services/app360-data-core/var`، وكان يعرض Node 24. لا يثبت هذا السجل القديم سبب كل محاولة لاحقة. لم نغيّر المفتاح أو حساب نور أو قاعدة الإنتاج، ولم ننفذ نشراً يدوياً على الاستضافة.

كان غلاف التشغيل يحوّل كل فشل أثناء تحميل الخدمة، بما فيه فشل إنشاء مجلد التخزين، إلى رسالة نقص اعتماديات. كذلك خدمة البيانات مستثناة عمداً من pnpm workspaces لإدارة مكتبتها الأصلية بشكل منفصل، لكن تثبيت الجذر لم يكن يجهزها إلا عند تنفيذ build منفصل.

## التعديلات

- `npm install` من الجذر يشغّل postinstall لتثبيت خدمة البيانات، و`npm run build` ينفذ التجهيز نفسه صراحة. يستخدم التثبيت lockfile الخاص بالخدمة ويفحص تحميل SQLite الأصلي على بيئة التشغيل نفسها. لا تُثبت مكتبات من الشبكة عند تشغيل الموقع.
- دعم معلن ومختبر لـNode 20 و22؛ Node 24 يعطي رمزاً صريحاً بدلاً من تشغيل غير مدعوم. لا يكفي تغيير Node؛ أعد تثبيت الاعتماديات على نفس بيئة الاستضافة.
- استيراد knexfile لا ينشئ مجلدات. تهيئة التخزين تحصل في مرحلة مستقلة، مع إنشاء المجلدات المتداخلة وفحص كتابة فعلي وإزالة ملف الفحص. لا fallback إلى قاعدة أخرى عند الفشل، ولا استبدال أو مسح لقاعدة موجودة.
- غلاف الخدمة يميّز فشل التخزين والاعتماديات وSQLite الأصلي والإعدادات والترحيلات. السجلات تحتوي رموزاً ثابتة ومرحلة الفشل وإصدار Node والمنصة، دون المسارات أو نصوص الاستثناء أو الأسرار.
- صفحة الدخول تميّز عدم جاهزية الخدمة عن رفض تخزين الجلسة في المتصفح؛ لا تلوم مفتاح الربط تلقائياً.

## النشر على SmarterASP

1. احتفظ بقاعدة المدرسة الحالية والمرفقات وملف البيئة. حدّث **مشروع المدرسة كله من main**، أو طبق باتش المدرسة المرفق فوق النسخة الكاملة السابقة. الباتش ليس مشروعاً كاملاً.
2. اختر Node 22 LTS. من جذر المدرسة نفّذ `npm install --omit=dev --no-audit --no-fund` ثم `npm run build`. عند استخدام pnpm، لا تتجاهل lifecycle scripts؛ ويمكن تنفيذ build صراحة. لا ترفع node_modules من جهاز Windows إلى Linux.
3. حافظ على APP360_REELS_BRIDGE_SECRET مطابقاً لمفتاح الريلز. لا تنشئ مفتاحاً جديداً ولا تنشر القيمة في السجلات أو المستودع. اترك APP360_DATA_CORE_ENABLED=1 وAPP360_ENABLE_SEED_LOGIN=0 وAPP360_PUBLIC_ORIGIN=https://school.yem1.com وAPP360_REELS_BASE_URL=https://yem1.com.
4. APP360_DB_FILE يجب أن يشير إلى **قاعدة المدرسة الحالية** في مسار دائم متاح لمستخدم Node، وAPP360_UPLOAD_ROOT إلى مجلد مرفقات دائم. لا تنسخ مساراً افتراضياً من مثال ولا تحول قاعدة عاملة إلى ملف فارغ. المسار الافتراضي القديم باقٍ إذا لم تضبط متغيراً. إنشاء مجلد var وحده لا يعالج رابطاً رمزياً معطلاً أو قرصاً للقراءة فقط أو مكتبة مفقودة.
5. شغّل `npm run doctor:data-core` من نفس بيئة الخدمة. لا ينفذ migrations أو seeds ولا يرسل طلبات إلى الريلز. يفحص التحميل والمكتبة الأصلية وكتابة التخزين وSELECT 1؛ إذا لم توجد قاعدة في المسار المختار فقد ينشئ ملف SQLite جديداً، لذلك تحقق من المسار أولاً.
6. أعد تشغيل المدرسة. افتح https://school.yem1.com/api/app360/health وتحقق من HTTP 200 وok=true وreels_bridge_configured=true. وجود هذا العلم يعني تهيئة الإعدادات، ولا يثبت وحده مطابقة المفتاح أو الوصول إلى الريلز.
7. افتح **رابط دخول جديداً** للطفل من المدرسة/الريلز؛ الرموز قصيرة الصلاحية وتستخدم مرة واحدة. اختبر ظهور اسم نور وعودة الجلسة دون إنشاء حساب تجريبي.

## تشخيص فشل الاستضافة

ابحث في stderr الخاص **بالمدرسة** عن `[APP360_DATA_CORE]`. يمكن مشاركة هذا السطر لأنه لا يحتوي مفاتيح أو مسارات. لا ترسل ملف البيئة أو رابط دخول صالحاً.

| error | المعنى والإجراء |
|---|---|
| data_core_files_missing | ملفات الخدمة الجديدة غير مكتملة؛ أعد رفع نسخة المدرسة الكاملة |
| data_core_runtime_unsupported | اختر Node 20 أو22 ثم أعد تثبيت الاعتماديات |
| data_core_dependencies_missing | ملف مصدر أو حزمة غير موجودة؛ راجع نتيجة build واكتمال الرفع |
| data_core_native_dependency_unavailable | مكتبة SQLite الأصلية لا تعمل؛ أعد build على نفس النظام وNode، وراجع toolchain لدى المضيف إن فشل |
| data_core_storage_unavailable | راجع reason مثل ENOENT/EACCES/EROFS/ENOSPC، والمسار الفعلي والقرص وصلاحية مستخدم الخدمة |
| data_core_database_unavailable | فشل فتح/تهيئة/ترحيل القاعدة؛ راجع النسخة الاحتياطية والصلاحيات والمساحة ولا تستخدم reset |
| data_core_configuration_invalid | أصل الربط غير صالح؛ استخدم أصل HTTPS فقط دون /api أو اسم مستخدم وكلمة مرور |

لا يلزم تعديل الريلز أو إعادة رفع باتشه بسبب هذا الإصلاح؛ التغيير كله في مشروع المدرسة. لا يمكن للكود إصلاح مجلد محجوب من المضيف أو رابط رمزي معطل أو مساحة قرص منتهية؛ لكنه يحدد الفشل بدقة بدلاً من التشخيص المضلل.
